# 数字听答门控：独立基础与接线要求

本文件描述 #90 的独立准备切片。这里没有可通过的正式验收入口、真实冻结凭据或候选发布功能。`number_gate` 接受调用方提供的判断和哈希，只做不可信预检；`number_holdout_ledger::record_attempt` 只记录一次消耗，不授予读取保留集的权限。另有[盲保留格式与受限读取基础](number-blind-holdout.md)，但在真实开发证据接线前无法产生生产读取凭据。无论自报检查如何填写，当前门控都不会返回正式通过。测试数据是合成的行为反例，不是模型质量证据。

## 成对统计与开发预检

一条配对记录对应同一原始录音，分别记录底座和候选的正确性与正常结束。没有正常结束的答案按错误计入；双方都正确、双方都错误以及只有一方正确的案例均在分母中。报告列出样本数、双方正确数、双方正常结束数、四格计数、正确率差和区间。

设全部案例数为 `n`，仅候选正确数为 `b`，仅底座正确数为 `c`。正确率差为 `(b-c)/n`。预先固定的方法分别对 `b/n` 和 `c/n` 计算双侧 97.5% Clopper–Pearson 精确二项区间 `[L_b, U_b]` 和 `[L_c, U_c]`，再报告 `[L_b-U_c, U_b-L_c]`。每个二项区间的单尾概率是 0.0125；Bonferroni 联合覆盖率至少 95%。计算以二项尾概率反演，不用只含不一致案例的分母。

这要求成对原始案例独立抽样，且每对中两组使用相同输入与可比设置。不同 ID 并不能证明真实独立性。当前预检采取保守口径：每条记录须有不同的说话人、会话、原录音和派生家族 ID，否则不提供独立区间；少于 30 对时证据不足。30 对只是研究方案的最低开发数量，不保证区间足够窄，也不证明人群代表性。满足数量后，正确率差至少 5 个百分点、95% 区间下界严格大于零且正常结束率不下降是必要条件。低于阈值、区间不支持正提升或结束率下降会列为预检失败原因；由于尚无真实来源验证，总体状态仍为证据不足，也不能晋级。

调用方声明的规则、训练/开发/保留数据承诺、分组、底座、候选、codec、核验器、比较方案、评估实现、参数及原始结果哈希，只检查格式，不会读取或证实其内容。各检查的 `Passed` 同样是调用方自报。即便所有声明和数值都好，预检仍报告 `InsufficientEvidence`，直到真实接线实现了下述重验。当前结构不保存音频、原始回答或完整评分过程，不能独立复现真实质量。

## 一次性占用账本

协作进程必须使用同一个本地账本目录。记录占用时，锁住该目录的 `ledger.lock`，验证现有账本，再将包含承诺、候选/协议声明和源身份的完整账本写入同目录临时文件；同步文件、原子替换，再同步目录和其父目录。只有操作完成后调用者才能继续执行自己的下一步；若替换已发生但同步或后续步骤失败，该保留集仍视为已消耗。进程在成功占用后退出也不解除占用。占用没有自动撤销或重试接口。

相同保留内容承诺、原录音身份或派生家族身份任一重合都拒绝另一占用；输出路径和清单名称不是账本身份。身份必须来自跨清单稳定的源登记，不能根据可变文件名自行生成。账本带校验和并拒绝损坏、未知版本或无效记录；锁不可用、I/O 失败也不放行。校验和只能发现意外变化，不能防止有写权限的人改写并重新计算。任何人还可以删除账本、复制数据、伪造来源身份或使用另一个账本；因此它只约束遵守同一协议的本地进程，不是防篡改服务。当前进程锁依赖 Unix，其他平台不支持占用。

## 正式接线前必须解决

- #82 的 v2 单个 JSON 同时含 train/dev/test 的数字和答案，训练/开发读取会暴露保留答案；其当前加载路径也在选择分区前解码所有 WAV。v2 可留作兼容实验，不能作为盲保留证据。正式格式须将保留敏感清单、答案及媒体隔离，预占用前只暴露稳定来源分组和内容承诺；禁止用可枚举的小数字明文哈希充当盲承诺，需使用独立保密随机盐及明确编码并在开放后验证。数据准备、训练和开发均不得读取或解码保留内容。
- 目前 #82 将规范化文本精确比较，因此 `十三` 与 `13` 不同；静音只统计碰巧等于原答案的输出。接线要固定有限语法和同值规则，证明 `十三` 等于 `13`、不等于 `十五`，并将静音时任何无依据数字计入相应错误。交换对照必须按实际音频来源评分；原始模型输出、条件、输入身份和规则答案均须保留。
- 正式门控须从真实执行的不可变报告、逐题原始结果、输入及规则真值、预注册协议、来源分组、模型/codec/候选/评估器和参数重算并核对绑定；不能把本模块的自报布尔值或哈希升级成真实证据。结果不足、未见真人来源/人工参考不足、输出语音 ASR/听审缺失、交换/静音对照缺失、中文/英文/其它 Omni 及预注册朗读/对话回归缺失均不能晋级。不同来源声明或哈希本身不证明说话人、许可、录音血缘和标注真实性。
- 只有重验过的开发结果与候选已冻结后，才能在共享账本中同步占用，再打开保留敏感内容、验证承诺并做一次独立报告。必须以真实文件访问边界和中断/并发测试证明顺序；单纯调用账本函数不能证明盲保留。保留集不得参与选型或反复调参，不自动启用或发布候选。
- 真实质量还需要许可允许的未见真人录音及独立参考、真实底座/候选与 codec 的原始报告、输出语音或绑定听审记录，以及完整能力回归。研究方案建议至少 120 条训练、30 条开发和 50 条独立保留；是否满足、来源是否独立必须在正式接线和实测中核验。以上均不改变 #82、#83–#85 的验收。
