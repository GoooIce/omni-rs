# 数字听答盲保留格式：独立基础

本模块提供保管人封存、公开承诺解析，以及“先占用、后读取并校验”的独立实现。它还不是 #90 的正式验收入口：真实开发报告重验和 #82 数据/评分接线尚未完成，生产代码没有 `VerifiedDevelopment` 的构造方法。调用方自报的布尔值或哈希无法创建该凭据；测试仅在测试编译中构造合成凭据，不能证明模型质量或授权真实数据读取。

## 公开内容与秘密内容

公开 JSON 只有 `version`、`content_sha256` 和 `sources`。每个来源只包含不透明的说话人、会话、原录音和派生家族 256 位身份；不包含题号、说出的数字、规则答案、音频名称或路径、盐。解析器拒绝额外字段、无效哈希、重复/未排序的原录音和未知版本。来源身份应从跨训练、开发和保留集共用的可信登记中取得；应使用高熵不透明身份或保密密钥派生的稳定身份，不要把小范围数字、可猜姓名或文件名直接哈希后公开。格式检查无法证明来源声明真实，也无法证明说话人或录音之间独立。

只有独立保管人进行封存：将内存中的保留清单交给 `seal_for_custodian`，由 OS 随机源生成 32 字节秘密盐，再调用 `persist_private` 建立新的私有目录。生成和写入阶段不读取、解码媒体，也不供训练或开发进程使用。目录和秘密文件分别以 0700 和 0600 创建，拒绝覆盖；盐保存在 `salt.bin`，精确的 UTF-8 清单保存在 `manifest.json`。媒体文件由保管人另行放入该目录，媒体文件名只在秘密清单中。只有全部私有文件准备妥当后才应公开承诺。

秘密清单中的案例包括题号、0–99 的输入数字、加一后的数值答案、私有 WAV 文件名及其字节 SHA-256、上述四类来源身份，以及 `private_source` 对象。后者用于保留许可、合成或真人来源、人工参考和核查记录，原样纳入承诺；它可以为空，其存在不代表已通过真实性或许可验证。当前格式固定加一规则，校验答案、唯一题号、简单文件名和同一原录音的分组一致性；版本由承诺的域和公开版本共同固定。案例和媒体名不放进公开信息。来源条目按原录音身份排序；打开后重新计算并与公开分组逐项核对。

清单承诺为 `SHA256(domain || salt || len || manifest)`，其中 `domain` 是 UTF-8 字节 `omni-rsi/number-blind-holdout/manifest/v1\0`，盐固定为 32 字节，`len` 是清单字节数的无符号 64 位大端编码，`manifest` 是封存时 `serde_json` 序列化的精确字节。媒体的实际字节通过秘密清单中的 SHA-256 间接绑定。公开元数据另用独立的 `omni-rsi/number-blind-holdout/public-metadata/v1\0` 域、64 位大端长度和规范化公开 JSON 计算指纹，未来的验证凭据必须绑定该指纹及冻结的协议、候选和真实开发证据。

随机盐防止从低取值范围的数字或答案枚举**承诺**；它不加密私有文件。保管人必须另行隔离实际目录及盐，保护父目录、访问控制列表和备份。模式位不能证明 ACL 保密，也不能隔离同一操作系统账号；有权读取文件或操纵进程的人仍能绕过盲法。

## 读取和失败语义

评估侧仅解析公开 JSON。未来只有真实证据验证器产生的不可伪造凭据才能调用正式读取路径。当前独立实现先核对凭据与公开元数据指纹，再通过共享账本为承诺及来源身份同步记录占用，之后才检查私有目录并打开盐、秘密清单和媒体。任何账本锁冲突、已用来源、记录损坏或占用失败都发生在私有文件访问之前。

占用之后依次检查目录与盐的私有模式位、常规文件与大小、盐长度、清单承诺和来源分组，再读取每个媒体并检查其 SHA-256；所有检查完成前不返回任何清单或媒体。文件打开拒绝末端符号链接。错误、进程退出和重试不会撤销已记录的占用：即使盐、清单或音频有误，也不得修复后用同一保留集重试。测试覆盖提前失败、锁冲突、盐/清单/媒体/公开承诺篡改、来源不一致、进程占用后立即退出、并发进程争用和重封同源数据。

账本是同一目录下遵守协议的本地协作约束，并非防篡改服务；它不能阻止有权限者删除或替换账本、复制数据、伪造来源身份或选择另一个账本。中断模拟使用仅在测试构建中存在的故障注入，不会进入生产代码。

## 剩余接线

当前读取器只验证承诺和媒体字节身份，不解码或验证 WAV 内容、许可、标注真实性、真人来源、跨切分隔离或完整 #82 数据准入；相应规则必须在占用后继续由真实数据路径验证，不得降低 #82 的验收。公开分组应在训练/开发阶段用于验证说话人、会话、原录音及家族互不泄漏，不得为此读取秘密清单。正式评估还须重验绑定真实运行的开发报告、原始成对输出、规则、模型/codec/候选、验证器、回归与冻结参数，才能生成真正的凭据；回归、真人参考或真实来源不足时始终是证据不足。随后还需修正并验证中文/阿拉伯数字同值、不同数字和静音对照口径，才可连接 #82 并开展一次保留报告。当前代码不发布或启用候选。

评分接线须从完整回答中识别无依据的数字，并保留逐题原文。例如静音时 `我听到的是0，加一就是1。` 和 `我听到的是“零”，加一就是“一”。` 都含无依据数字，不能因未碰巧等于原题答案而漏计。2026-11-10 的两道合成题探索报告中，两组在原题和交换题均为 0/2，旧的 `silence_matching_original` 却为 0；该报告用于暴露评分缺陷，不能证明正式模型质量，输出语音和各项能力回归也未运行。
