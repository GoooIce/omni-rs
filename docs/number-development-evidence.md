# 数字听答开发证据：当前边界与后续接线

当前评分接口接收调用方提供的逐题原文，按实际原音频、交换音频和静音条件重新计算结果；它不接受“正确”布尔值作为答案真值，也不因此证明这些输出来自真实模型。任何调用 `summarize` 或 mock 推理得到的报告都固定为 `insufficient_evidence`、`candidate_eligible=false`，不能构造保留集读取凭据。原文、输入身份和正常结束状态留在报告中供复算。

[独立 v3 数据入口和开发协议预注册](number-development-preregistration.md)提供输入隔离、目标语音码和显式训练路径。新增的 v3 本地比较可以执行真实开发推理，但尚不能完成正式验收；格式及 mock 测试不能作为联合训练质量的证据。

`number_audio preregister-v3 MODEL DATA STATE REGISTRATION` 在训练后检查 v3 检查点、实际模型与数据、当前评估程序和已有回归计划，再在新目录冻结协议及 `v3-evaluation-policy.json`。`number_audio dev-v3 MODEL DATA STATE REGISTRATION REPORT` 只接受该注册：重算身份并使用冻结的不同答案一对一交换，在底座和候选上各运行原音、交换音、等长静音；每次使用全新 cache，并保留逐题原文、实际音频 PCM 身份、臂、条件及终止原因。评估只向模型提供固定指令和 PCM。注册和报告均不可覆盖，过程持有前台、设备、父状态及实际检查点目录的训练租约。

发布前失败或取消不会发布完整报告；报告或注册策略文件成功发布后，若父目录同步失败，错误会明确提示文件已发布但持久化未确认。此时文件可能存在且不可直接用同一路径重试，操作者应检查原工件；程序不会自动删除或覆盖它。语音输出目录在生成前独占创建，失败或取消可能留下不完整目录，同样不会自动覆盖或删除。

显式本地权重验证可运行 `number_v3_train` 测试中被忽略的 `v3_real_registered_development_with_local_weights`，先设置 `LFM3_MODEL`、`LFM3_NUMBER_V3_DATA`、`LFM3_NUMBER_V3_STATE`，使用匹配源码训练出的检查点，并传 `-- --ignored --exact`。探索数据的假盲承诺只能用于烟雾检查；该测试的成功不表示来源、回归或模型质量已验收。

冻结文本解码策略记录由实际模型配置和生成配置解析的停止/抑制 token、上下文长度、后端，以及 FP32、贪心、32 token 和 16 kHz；真实文本生成直接使用生成该记录的同一组选项。评估前后重验模型、候选、数据、二进制、策略和注册；加载到内存的检查点也按保存使用的规范 JSON 重算身份。配置和代码身份约束遵守流程的本机运行，不能作为操作系统对进程映像或真实来源的认证。

提供 `--r2t2-model MODEL --r2t2-binary BINARY` 时，注册和运行均可显式选择 `--r2t2-mode cpu-f32` 或 `metal-f16`；省略模式保留 Metal/F16 默认。注册后 `dev-v3` 必须使用同一模式、同一工具身份，并额外指定尚不存在的 `--voice-dir DIRECTORY`。两个模式均由 v3 执行器显式传入全部已冻结的 R2T2 选项，包括布尔值；CPU/F32 的中间 token 上限为 32，Metal/F16 为 4，最终上限均为 128。任一转写事件报告截断、取消或缺少状态均失败关闭。所选 R2T2 二进制须支持 `--json=true`、`--realtime=false`、`--warmup=false` 和 `--no-cache=false`，旧二进制若不接受这些参数会报错，需选择支持这些参数的新构建并重新注册。R2T2 原有不带值的布尔开关仍可使用；只有 `--warmup=true` 才要求 `--audio`。v3 不修改独立自朗读的执行器或检查点协议。语音生成的停止条件、采样参数、codec 格式和 R2T2 参数均冻结并重验。未配置 R2T2 时输出语音明确为 `not_run`；`--breeze-model`/`--breeze-binary` 只绑定身份，五类回归也只冻结输入，均未执行。

例如，在操作者已准备好本地模型、匹配的训练状态和隔离数据后，可用同一构建程序显式注册和比较（`REGISTRATION`、`REPORT`、`VOICE_DIR` 均须是新路径）：

```sh
cargo run --offline --locked --manifest-path crates/omni-rsi/Cargo.toml --no-default-features --features native,cpu --example number_audio -- \
  preregister-v3 "$MODEL" "$DATA" "$STATE" "$REGISTRATION" \
  --r2t2-model "$R2T2_MODEL" --r2t2-binary "$R2T2_BINARY" --r2t2-mode cpu-f32
cargo run --offline --locked --manifest-path crates/omni-rsi/Cargo.toml --no-default-features --features native,cpu --example number_audio -- \
  dev-v3 "$MODEL" "$DATA" "$STATE" "$REGISTRATION" "$REPORT" \
  --r2t2-model "$R2T2_MODEL" --r2t2-binary "$R2T2_BINARY" --r2t2-mode cpu-f32 --voice-dir "$VOICE_DIR"
```

语音目录保存每个条件/臂的原始 tokens、codec 帧和 24 kHz float WAV，报告记录相对于 `--voice-dir` 的文件名、SHA-256、生成结束原因、有效性、转写原文与按实际输入答案计算的逐题 CER；应同时保留报告和完整语音目录以便复核。按臂和条件统计的 `mean_case_cer` 是已有逐题 CER 的算术平均，并记录可计算题数。有效性只检查帧形状、码值、结束标记位置及有限非零 PCM，不证明可懂度或语音质量；正常结束还要求已登记的文本停止 token 和最终全码本 EOS。有效但异常结束的语音可以计算转写 CER，数字正确标志仍为假；不能仅凭 CER 判断通过。无效音频不运行 ASR，CER 为 `null`；全部或部分无效时分别标记 ASR 未运行或部分运行。静音没有规则答案，CER 为 `null`。CER 沿用既有字符口径，数字同值另用现有数字评分判断。R2T2 返回空语种时保留空原文并标记 `unknown`，不据此推断中文。即使没有截断标记，ASR 仍可能漏词；生成语音的独立人工听审仍未完成，工具转写不是人工真值。

语音比较预先限制最多 6,000 条条件观察（即 1,000 个完整开发题）、每条最多 180 个生成 slot 和 30 秒输出、总输出不超过 1,200 秒；生成期间逐 PCM 事件检查当前条目和累计余额，超限立即停止并拒绝报告，不抽样截断。生成器在回调前已分配并追加当前事件，因此最多可能暂时多持有一个越限事件的 PCM。CPU/F32 R2T2 每条通过独立本地进程调用，单次超时为 1,200 秒；Metal/F16 为 300 秒，均写入注册策略并支持取消。11.52 秒语音的单条 CPU 诊断曾花约 329 秒，说明原 300 秒不够；新上限仍不能保证所有输入完成，诊断不回填原先失败的比较。标准输出/错误在进程退出后检查 4 MiB 上限，运行期间的临时文件增长不能视作严格磁盘配额。模型和工具目录仍须由操作者保持可信、稳定并与保留秘密隔离。

报告中的数字评分复用已有中文/阿拉伯数字和静音字面规则，成对统计复用 `number_gate`；其来源独立性仍只是分组声明。`silence_numeric_rate` 是输出中出现数字字面的比例，不等同于幻觉率，例如“请再说一遍”也可能被计入。当前真实或注入执行均固定为 `insufficient_evidence`、`candidate_eligible=false`，不构造保留集凭据、不读取保留秘密或发布候选。注入回调标记为 `injected_unverified`，不能作为真实执行或质量证据。

## 开发文本观察的复算预检

`recheck_registered_observations` 接受已注册的 train/dev 快照和一份不可信报告，核对协议身份，并要求每个开发案例恰有两臂各三条原音、冻结交换和等长静音观察。它依据注册中的实际 PCM 重算输入哈希与样本数，按换入音频的规则答案及完整静音原文重新计算文本结果、正常结束计数和成对统计；缺失、重复、换音频、PCM 不符、逐题分数或汇总不一致会拒绝。数值门槛只按声明的来源 ID 与报告的结束事件计算：30 个不同 ID、至少 5 个百分点及预注册的 95% 区间下界；不同 ID 不能证明真实说话人或来源独立。

通用预检不持有 v3 生成策略，`termination_token_policy=not_checked`；它只能识别停止事件的结构，不能确认 token 合法，文本结束计数及其数值门槛只是暂定值。受控 v3 路径在输出报告前，使用重新核对过的冻结策略验证每个文本停止 token，并写入 `observation_recheck`；`matched_registered_tokens` 只表示 token 与这份策略匹配，不证明真实模型执行。它单独比较原音、交换和静音的文本正常结束计数，不把语音结束冒充文本结束或反之。

此复算尚不验证语音帧、WAV、R2T2 转写/CER 或语音听审，不执行或重验五类回归，也不核实授权、人工参考或来源声明。报告中的执行字符串、自报通过、内容哈希和不同 ID 都不能代替这些证明；无论输入是真实路径报告还是注入/mock 结果，本预检始终返回 `insufficient_evidence`、`candidate_eligible=false`，不能构造 `VerifiedDevelopment`。正式接线还需受控的真实执行上下文、可追溯的来源授权和独立真人审核、冻结回归的实际执行与重算、语音工件及 ASR/CER 验证、内部签发凭据和占用后的单次保留报告。它们均不得依赖调用者声称通过。

当前有效但异常结束且末帧为 EOS 的语音可能被现有检查器误判为无效并跳过 ASR；这与上面的目标行为不一致，须在正式语音资格接线前修复并测试。评估源码身份发生变化，旧 v3 注册不会通过当前源码重验；保留原注册和二进制，用新目录重新冻结，不覆盖或静默迁移。

本语音评测切片不修改训练源码或 `number_development.rs` 的数据、冻结交换实现；相对于相同训练基线，不能仅凭它要求重新训练。它扩展了评测入口的预注册策略，评测程序和策略身份会改变，因此旧注册不得伪装迁移，应保留旧文件及原二进制，并用新评测程序选择新的注册目录。其他合并若改变训练实现或数据源码，须按其实际检查点身份单独判断兼容性。

真实本地评估入口沿用训练协议：从模型目录、codec、实际数据快照和候选检查点计算身份，运行后重新核对；还记录评分/比较相关源码与锁定依赖的指纹，以及评估程序文件运行前后的 SHA-256。报告中的评分协议固定整数判定和静音字面检测方法。程序文件哈希是对磁盘文件的变化检查，不是操作系统对进程加载映像或实际计算的证明；来源、授权、人工标注等声明也不会因哈希存在就变真。

目前仍没有可信的开发集验收凭据。尤其是现有 v2 单文件数据会读取 test 的答案和音频，只能作已暴露的实验数据，不能接盲保留验收；真实来源、输入转写核验、输出语音听审、中文/英文与其他 Omni 回归若缺失均为证据不足。两道合成题的烟雾报告只能作为评分反例，不证明候选改善或真人泛化。

后续接线应满足以下顺序：

1. 在模型运行和任何保留敏感内容读取之前，持久冻结规则、评分实现、训练/开发数据和保留公开承诺、说话人/会话/录音/家族分组、固定交换映射、底座/codec/候选、评估器、R2T2/Breeze 身份和全部解码及回归参数。验证训练、开发与保留公开分组互斥；真实保留答案、盐和媒体不能作为开发输入。预注册文件必须不可静默覆盖并可复算其内容身份。
2. 由实际 Rust/Burn 本地执行路径生成逐题原始观察，保留双方原文、实际输入音频身份、条件、正常结束及必要的输出语音/转写记录。只依据真实数据规则和原始记录重新计算正确性与控制项；mock 推理、caller-supplied 报告、布尔声明、单独的哈希或自报 `passed` 都不能产生真实执行证明。中文/阿拉伯数字、不同数字、完整句静音数字及歧义例须使用固定判定口径。
3. 对独立原始案例和来源作成对统计：至少 30 个独立案例及说话人/会话/录音/家族，准确率差至少 5 个百分点，预注册的 Bonferroni/Clopper–Pearson 95% 区间下界严格大于零；全部条件的正常结束率和预注册能力回归不得退化。样本不足、依赖、未经核验的真人参考、缺失回归、输出音频/听审或任何控制项不满足时，不生成正式通过。
4. 只有实际执行路径及验证器完成上述检查后，才在模块内部创建绑定冻结协议、原始结果、候选和保留公开元数据指纹的不可伪造 `VerifiedDevelopment`；不能提供接收任意调用方布尔值或哈希的公开构造器。随后才使用同一本地账本原子占用，再读取并验证盲保留内容；中断仍视为消耗，不自动发布或启用候选。

这些措施为遵守协议的本地进程提供可审计的顺序和防误用约束；具有同一账户文件或进程控制权的人仍可绕过或伪造本地工件，不能把它们宣称为远程硬件认证。
