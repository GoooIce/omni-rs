# #82 真人数字语音来源：一手资料补查

核查日期：2026-11-11。先读了[已有来源梳理](lfm3-omni-number-human-sources-2026-11.md)；这里补充此前未详查的发布方页面、原论文、许可和公开元数据，不重做已有 AISHELL、Common Voice、OMPAL、ManDi、FLEURS、SHALCAS 等结论。**AliMeeting 公开训练近讲包已下载、校验并提取训练转写，初步文本筛查结果见下文。**随后从已查看文本的训练资料中选取了四段录音用于非盲探索；没有读取项目既有保留集、创建账号或联系发布方。筛查尚未核对声音、语义歧义或说话人独立性。

## 结论

**本轮没有证实任何来源同时满足：普通话真人、足量可分组的未见说话人、合格数字话语、独立人工参考、适用许可及免账号下载。**这不是对所有公开语料不存在性的证明。**AliMeeting** 的训练转写粗筛找到 107 条数词写法、涉及 81 个文件名中的匿名编号；随后 Rust 筛查器将这 107 条全部列为待审，自动候选为 0。它们不是已合格案例或独立真人数。其原论文提供训练部分 456 人，发布页列出 CC BY-SA 4.0；跨会话分组、声音内容与逐题盲听均未证实。**MagicData-RAMC** 是非商业且不分享改编材料条件下的另一条线索，已有人工转写和专业校对；许可及数字覆盖仍是限制。KeSpeech 的多人复核流程尤其清楚，但自定义许可和获取条件限制较强。

以下人数均是原语料或其原训练分区的人数，**不是符合数字任务的说话人数**。本次筛选以 30 名以上可分组说话人为优先条件；项目现有[开发证据要求](../number-development-evidence.md)另要求至少 30 个独立案例及相关隔离与统计，不能用总人数代替。

### AliMeeting 训练近讲包：下载与初步文本筛查

2026-11-11，对 [OpenSLR 发布的训练近讲包](https://speech-lab-share-data.oss-cn-shanghai.aliyuncs.com/AliMeeting/openlr/Train_Ali_near.tar.gz)进行了前 **4 MiB** 的 HTTP Range 结构探查，获得 **4,194,304 字节**；另以范围 HEAD 请求核实服务器支持 `206` 响应。从截断的 gzip 流可列出根目录、`audio_dir` 和第一个约 65 MB 的 WAV 条目；范围探查未提取音频或访问项目保留集。该前缀不足以证明整个归档的结构，更不能说明转写是否存在或数字覆盖情况。

随后以 **8 MiB/s** 限速断点续传该公开训练近讲包，完成大小为 **24,530,908,701 字节**，与 HTTP HEAD 一致；`gzip -t` 通过，本地 SHA-256 为 `4c6512112f0f23bdfe535b8878c0ff140eb267b37c923b8794171edcc5d5d996`。这是本地计算的身份值，未与发布方独立摘要比较。文件保存在 `artifacts/audio-rsi-p0/alimeeting-archive-probe-20261111/train-near.tar.gz`，不随仓库提交。归档清单有 683 个 WAV、683 个 TextGrid 和 3 个目录，未发现特殊文件、异常或重复路径；录音与转写的文件名去扩展名后逐一对应。首次筛查只提取 `textgrid_dir`，共 683 个普通文件、约 21 MiB；后续另外提取了下述四个 WAV。

文件名均含数字 `SPK` 后缀，共 452 个不同后缀；同一后缀可跨录音重复。683 个转写均有一个 `IntervalTier`，其中 682 个层名为 `c1`、1 个为 `S3`，因此层名不能用作跨录音的说话人标识。文件名编号只是发布方标识，尚未证明与自然人一一对应；论文报告的 456 名参与者也不能直接当作本次编号数或合格数字人数。

探索性正则仅查找一整行标注中独立书写的 0–99 数词，不做 NFKC、相邻片段或语音核验：得到 **107 条文本候选，涉及 81 个 `SPK` 后缀**。其中有 22 条写作“一”、8 条写作“两”，可能存在语境歧义；数词语义、实际声音、切分边界、许可用途及说话人／会话隔离都未验证。规则脚本 `artifacts/audio-rsi-p0/alimeeting-archive-probe-20261111/rough-whole-number-screen.sh` 的 SHA-256 是 `78b9abe7754671035d492f23c9347db65efec9409ef9f6211ce6a5ac7c3b25b2`，聚合结果保存在同目录 `rough-whole-number-results.txt`。这不是完整语言解析，也不是受控 Rust 筛查器的最终结果；不能据此声称真实未见说话人、独立听审、模型改善或正式验收通过。

之后用本地 Rust 筛查器处理了全部 **683 份转写、186,606 个区间**。按当前保守的相邻非空标注规则，**自动候选 0 条，107 条待审**，待审项涉及 81 个文件名 `SPK` 后缀；全源文件共 452 个不同后缀。这与粗筛的 107／81 数量一致，但两者的筛选语义不同，不能把待审项算作合格样本。输出保存在本地 `artifacts/audio-rsi-p0/alimeeting-archive-probe-20261111/screen-results/screen-v1.json`，文件 SHA-256 为 `08ace448dad0419f356475a540f8dd3570f86c6ec568202138e14caa275d4c3b`；筛查器报告的源快照身份为 `1b3611f715cb83e1401c2ce987abbf2bc884dcf3f5ad09e632d1d1292c05ffec`、工具身份为 `fd50e89ee7c3479f197c3fcae7f6913076792be74c71da762ac59b8363335336`。这些本地身份值不代表发布方认证或音频核验。

为了小规模检查训练管线，在已经查看训练文本之后，先固定四个不同文件名说话人后缀和会议的训练／开发分组，再仅提取这四个源 WAV，按标注时间裁成 16 kHz 单声道片段；固定方案、裁剪脚本、源和片段的哈希及格式记录均留在本地 `artifacts/audio-rsi-p0/alimeeting-human-number-smoke-20261111/`。它们均来自待审项，未经独立盲听；最后一段与后续标注紧邻。此分组是**非盲探索，不是保留集、独立说话人或质量验证**，且不同文件名后缀不等于已经核实不同自然人。搭配的已有本地 Breeze 合成中文目标还受其研究／非商业条款约束，声音内容尚未核实。

## 新增候选和边界

### 1. AliMeeting（SLR119）：优先查文本元数据

- [发布页](https://www.openslr.org/119/)称这是真实普通话会议语音，提供近讲和远场通道，许可为 **CC BY-SA 4.0**，页面列出训练音频大包的直接链接。[原论文](https://arxiv.org/pdf/2110.07393)的训练分区包含 212 场会议、456 名参与者；每场 TextGrid 描述逐段转写、起止时间及说话人 ID。[挑战总结论文](https://arxiv.org/abs/2202.03647)称训练分区有人工转写及时间戳。
- **未证实：**数字独立话语、0–99 覆盖、合格数字片段所涉的不同说话人数，以及跨会议 ID 是否稳定地对应同一真人；未找到证明针对数字进行了互盲转写或听审的说明。会议的交叠、口误、上下文和切段边界还需逐题核验。近讲与远场是同步录制，不能当独立原始案例。
- [CC BY-SA 4.0 正文](https://creativecommons.org/licenses/by-sa/4.0/legalcode.en)规定署名和分享改编材料时的相同方式共享条件；是否及如何适用于拟发布的具体产物，要结合实际产物核对。未找到发布方单独提供训练 TextGrid 的可验证地址；本次从完整训练包中提取了转写，归档未见单独许可文件。其他适用条款也未验证。

### 2. MagicData-RAMC（SLR123）：人工转写、校对及逐段 ID 较明确

- [发布页](https://www.openslr.org/123/)和[原论文](https://www.isca-archive.org/interspeech_2022/yang22h_interspeech.pdf)称该普通话自然对话集有 663 名说话人、180 小时，每个录音由一名标注员标注，转写和切分经专业检查人员校对；每段含说话人 ID。其[自称官方的资料仓库](https://github.com/HaoranMiao/MagicData-RAMC)列出训练分区 556 名说话人，并说明 `SPKINFO.txt`、`UTTERANCEINFO.txt` 和逐段时间／说话人／转写字段。专业校对不等于已证明两名听审者对数字独立盲听。
- **原分区存在不能忽略的隔离疑点：**同一篇论文报告全库 663 名说话人，而训练／开发／测试分区分别报告 556、38、86，合计 680；论文还称一人最多参与三次对话。若这些数均为同口径独立说话人数，则至少有跨分区重复计数；也可能存在统计或版本差异。本轮没有读取任何分区明细，无法判断具体重合者或重合在哪两个分区，**不能把原分区默认当说话人互斥**。
- 数字覆盖、完整数词话语与对应说话人数均未知；原始材料是对话，不应把出现数字的任意句子或强制切分片段直接当孤立数词。发布页列出一个含音频和标注的 15 GB 包；本轮未下载，也未确认单独的训练转写下载地址或实际免账号访问。
- 发布页标 **CC BY-NC-ND 4.0**。依[许可正文](https://creativecommons.org/licenses/by-nc-nd/4.0/legalcode.en)，需区分非商业用途和分享改编材料的限制；不能由此断言一切私下技术处理都被禁止，也不能在拟分享裁剪／改编语料或有商业用途时假定已获许可。

### 3. KeSpeech：人工复核流程强，授权及获取受限

- [原论文](https://datasets-benchmarks-proceedings.neurips.cc/paper/2021/file/0336dcbab05b9d5ad24f4333c7658a0e-Paper-round2.pdf)称全库 27,237 名说话人，包含普通话和八种官话次方言；按论文表格，第一阶段普通话部分有 22,621 名说话人。论文描述一人标注、另一人全量检查、第三人抽检，并称各阶段的文本被检查和更正。它说明 `phase1.text`、`phase2.text`、`utt2spk` 等元数据及说话人匿名化；两阶段多数说话人重复，不能相加当独立人数。
- 文本源主要是新闻片段，论文称候选片段通常 12–18 个汉字；没有证实独立数字话语、0–99 或数字子集人数。虽有多人校验，仍未证明针对本任务数字的独立盲听；匿名 ID 也不保证与其他语料的真人完全不重合。
- [自定义许可](https://github.com/tzyll/KeSpeech/blob/main/dataset_license.md)限非商业，允许必要技术修改但禁止演绎，并禁止向第三方分发数据；适用到计划中的筛选、剪裁及产出时需先明确。论文还描述研究计划／申请审核，而[仓库 README](https://github.com/tzyll/KeSpeech)给出带提取码的网盘分享并称下载即同意许可；两者在获取／使用流程上需要进一步厘清，本轮未打开网盘或确认免账号。即使可访问，也不能把它视为宽松开放许可。

## 可复现的后续筛选步骤

下列步骤是后续核验协议；AliMeeting 训练转写已有初筛，但尚无经声音及来源核实的样本。归档本身未见许可文件，使用时须遵守 [OpenSLR 的 CC BY-SA 4.0 标示](https://www.openslr.org/119/)，并确认拟议使用、署名及分享条件；不读取项目既有保留集。

1. **固定来源与许可。** 记录上述发布页、论文版本、访问日期、具体发布版本和许可正文；取得文本／元数据后记录 URL、文件清单和 SHA-256，并遵守适用的许可和任务授权。确认实际用途、改编和分享方式以及匿名访问条件；不要用第三方镜像的标签替代发布者许可。上述 AliMeeting 本地筛查记录了所用源快照身份，其他候选尚无对应的逐条快照。
2. **仅处理允许的开发候选范围。** 对 AliMeeting，依据原论文的训练 TextGrid 提取会话 ID、匿名说话人 ID、段起止及原始逐段文本；对 RAMC，依据官方仓库字段关联训练范围的 `SPKINFO.txt`、`UTTERANCEINFO.txt` 和逐段标注；对 KeSpeech，若条款允许，使用对应阶段文本及 `utt2spk`、方言标签。只统计获准的训练／开发候选，**不读取项目既有保留材料**；无法合法取得文本或核实来源时记为受阻。
3. **先筛整段，再单列语境。** 以以下 `whole-number-v1` 规则做保守文本粗筛，并保存规则及其 SHA-256：对文本做 Unicode NFKC，只移除首尾空白及 `,，。.!！?？、:：;；`，保留原文；其余字符不删除。整段必须完全匹配下述任一项：

   - 0：`零` 或 `〇`；1–9：`一二三四五六七八九` 分别对应 1–9，另把单独的 `两` 列为 2 的候选。
   - 10–19：`十` 或 `一十`，后可接一个 `一二三四五六七八九`，加上对应个位；20–99：`二三四五六七八九` 中一个字加 `十`，后可接同一个位字符，加上对应个位。
   - 阿拉伯数字只接受 `0`、`1`–`9` 及无前导零的 `10`–`99`。其他写法不强行归一化，计入未匹配／待审；这套表不是穷尽性的数字语言解析器。

   输出每段原文、规范化文本、候选数值及规则版本；以上只是**文本候选**。另可用数字字符片段查找完整句的待审候选，人工确认只有一个完整且语义明确的目标后单列“语境组”，不得与孤立数词合并。日期、时间、电话号码、逐位读数、多个数字、语气词或有歧义的文本进入待审／排除组；例如“二零”不自动等于整数 20，阿拉伯数字的写法也不能证明实际读法。
4. **输出可复算的汇总。** 固定筛选前总段数、完整数词候选数、语境候选数、待审与排除数；按数字、匿名说话人 ID、会话及原始录音分别去重计数，并给出每数字／每说话人的分布。近讲、远场、切片或变速等同源派生须归同一录音家族。ID 的数量只表示可区分的发布方 ID，不能自动证明不同自然人；跨会话 ID 不稳定时不得声称说话人隔离。
5. **由受控流程验证未见性。** 在任何选题和模型运行前冻结任务、候选数据和分组；由保留集管理方在隔离环境对说话人、会话、原始录音、文本及派生家族做冲突检查，只返回通过／冲突等非敏感结果。不能依靠文件哈希单独证明变速／裁剪及跨语料说话人独立，也不得尝试去匿名。还须核对基座模型公开训练来源和已知污染：项目内未使用不等于能证明模型预训练从未见过该真人或录音；证据不足应限制“未见”的声明。
6. **在许可允许的范围内做逐题听审和评估。** 由独立听审者在不看提示文本、模型答案及彼此结果的情况下记录实际听到的数字；保留分歧，复核后仍不明确的题不作确定真值。核查是否完整、单人、无重叠、无静音及边界是否截断；语境组与孤立数词分别报告。之后才可依据冻结协议构造模型不可见答案、配对对照和统计；不能把现有文本、强制对齐或模型自报充当人工参考。
