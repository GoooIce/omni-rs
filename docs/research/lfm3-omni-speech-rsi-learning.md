# LFM3-Omni 语音 RSI：从可验证的音频条件回答开始

研究记录，2026-11-10。本文中的“建议”和门槛是工程方案，不是论文结论；尚未运行本文提出的实验。外部材料仅作为各自模型、数据集或评测的证据，不代表本机已具备同等能力。

## 结论与现有反证

1. **先做离线、音频条件的中文短答，再做可打断的流式系统，最后研究真正的同时听答。** 首先证明输出确实依赖用户声音；现有自朗读训练没有证明这一点。[训练损失](../../crates/omni-rsi/src/speech_training.rs)、[LFM3 训练前向](../../crates/lfm3-omni/src/model.rs)
2. **语气理解和跟音乐哼唱共用 RSI 基础设施，分开构建训练任务和验收。** 前者需要有分歧标注的说话风格数据和人工独立评估；后者需要带声部和真实时间对齐的成对数据、音高及延迟验证。两者都不能从同一转写伪标签自动推出。[RAVDESS 数据](https://smartlaboratory.org/resources/speech-song-database-ravdess/)、[M4Singer](https://m4singer.github.io/)
3. **现有中文语音没有被证明改善。** 本次独立 Metal 实验运行一轮、6 次 LoRA 更新，以 R2T2 评估固定开发集 10 题（5 朗读、5 对话）：基线 CER 60.3%，候选 87.2%；正常结束 10/10 对 8/10，候选未晋级。轮次、更新次数及逐题结果见[原始报告](../../artifacts/chinese-speech/quality-native-v1/speech-native/epoch-1.json)，汇总见[本机报告](../../artifacts/idle-quality-validation/quality-summary.json)。这是小开发集反证，不是总体质量估计；对话组参考文本仅 10 字，整体 CER 对插入错误非常敏感。
4. [LFM3 官方模型卡](https://huggingface.co/LiquidAI/LFM3-Omni-2B)提供音频输入、文本与语音输出和中文支持的信息；交错输出文本与语音不等于能在播放时持续吸收新的用户音频。官方能力声明也不证明本机的双工、语气理解或哼唱质量。

## 当前仓库的接缝和缺口

| 组件 | 已有能力 | 不能据此声称 |
| --- | --- | --- |
| [AudioInputStream](../../crates/lfm3-omni/src/input_stream.rs) | 接收增量音频，编码完成的前缀可用 snapshot 取出，结束时处理尾部 | 前缀可以自动插入正在生成语音的同一上下文；系统已同时听与答 |
| [LiveTranscription](../../crates/lfm3-omni/src/live.rs) | 增量转写 | 语音回答时的双向对话与打断处理 |
| [OmniModel](../../crates/lfm3-omni/src/model.rs) | 准备音频媒体；对固定输入生成文本、语音码和 24 kHz 音频块 | 正在输出时可靠地更新输入、缓存和因果状态 |
| [语音训练](../../crates/omni-rsi/src/speech_training.rs) | Burn 自动求导、AdamW、冻结底座和小型卷积 LoRA，采样语音帧及结束帧损失 | 当前损失已训练音频条件回答：teacher_forced_speech_states 只接收 messages 和目标帧，内部准备提示时没有输入媒体 |
| [中文语音 RSI](../chinese-speech-rsi.md) | 显式开启的用户音频入队、R2T2 伪转写、语音编解码、候选开发集门槛和 CLI 显式加载 | 在线录音中的 ASR 伪标签自朗读等同于从语音学习回答；R2T2 对同源音频的往返一致性等同于独立正确性 |
| [音乐模块](../../crates/omni-music/README.md) | MERT 输出 pooled 1024 维表征；SheetSage2 离线转谱；YuE 使用其支持的文本及 ABC 等输入生成音乐 | MERT 是现成实时情绪裁判；SheetSage2 是实时转谱器；YuE 可任意接收 MERT 表征并条件化实时跟唱。SheetSage2 固定填充至 300 秒 |

输入前端使用 16 kHz 音频，400 点窗和 160 点 hop；编码器三层 stride 2 的下采样合计为 8。[前端常量](../../src/audio.rs)、[编码器实现](../../crates/lfm3-omni/src/audio_encoder.rs) 本机音频 tokenizer 配置为 24 kHz、每帧 1920 样本，即标称 80 ms，但输入 token、输出 codec 帧和实际设备播放时间不因此自动对齐。[官方 tokenizer 配置](https://huggingface.co/LiquidAI/LFM3-Omni-2B/resolve/main/audio_tokenizer/config.json)、[codec 实现](../../crates/lfm3-omni/src/codec.rs) 编码缓冲、重采样、尾部和设备延迟均须实测。

## 统一的真实时间数据协议（建议）

每条样本保存不可变清单和来源哈希；原音频与派生音频分开，保存采集许可、说话人匿名 ID、会话、设备、语言、任务、样本家族及 train/dev/test 分组。模型、ASR、TTS、codec、人工标注版本和置信度分别记录；禁止把伪标签标成真值。[现有采集与排除边界](../chinese-speech-rsi.md)

| 字段 | 要求 |
| --- | --- |
| 主时间轴 | 一个会话的单调时钟原点；每段输入、模型决定、生成、实际扬声器播放均记起止时间，分别保留原始采样索引和采样率 |
| 时钟映射 | 麦克风、播放和伴奏各自的设备时钟、重采样比例、滤波延迟、设备缓冲、漂移和丢帧；校准不确定度，禁止假定回调时间等于真实出声时间 |
| 声道与来源 | 用户输入、助手实际播放参考、背景音乐及可用的独立干声分别标记；真实混音不能冒充干净分离声部；记录回声消除配置和失败 |
| 事件 | 用户开始/结束、重叠、停顿、附和、打断、助手开始/停止/取消和背景声；区分静音、未知标签、缺失数据和输出结束码 |
| 因果边界 | 每个决策记录可见输入前缀终点；训练只能输入该时点已到达的信息，未来音频和人工事后标签只能作为目标或评估；音频输出目标按实际参考时间和 codec 帧映射 |
| 播放状态 | 区分已生成、排队、已播放和已取消的片段；记录实际设备出声与停止，不能用模型生成时间代替听觉延迟 |

配对合成音频适合检查时钟、串音和控制链路，但合成时序不等同于真实人类对话。真实混音还须包括扬声器回声、噪声、耳机/外放及不同设备；数据格式和计时机制属于工程建议，不是 [Moshi 论文](https://arxiv.org/abs/2410.00037)在本项目上的实测。

## 三个技能：训练、教师与独立验证

### P0 → P2：边听边答

- **P0，音频条件短答：** 每条样本包含用户真实或获许可合成语音、独立确定的标准答案文本和对应目标语音；优先选择答案随输入改变的封闭任务。冻结底座，复用现有 Burn LoRA 优化器，扩展 teacher-forced 前向以接收音频 PreparedMedia 并按提示位置拼接；先单独验证音频到答案文字的条件损失，再增加答案语音码及结束帧损失，不把用户原话当答案。[当前训练前向](../../crates/lfm3-omni/src/model.rs)、[当前损失](../../crates/omni-rsi/src/speech_training.rs)
- **教师：** 标准答案由任务规则或人工审核给出，Breeze 可朗读已审核答案形成语音目标；使用前核对模型和数据许可。语音教师只是目标音色，不负责判断答案正确。[Breeze 实现说明](../breeze-tts.md)
- **验证：** 固定未见说话人和会话，以无适配器底座为配对对照，比较答案准确率、正常结束率、声学可懂度和输出时延；盲听抽样复核。将同一提示的输入音频置静音、交换或替换成不同答案，检查输出是否按声音内容朝正确答案变化，而非仅仅变得不同；固定文本提示不得包含答案。项目内 R2T2 用于辅助转写，人工判读及规则答案提供独立于伪标签的信号。
- **P1，可打断流式系统：** 先把增量前端、端点检测、播放队列和取消机制连起来；同时采集不代表模型已同时理解。可先在输入充分后作答、在用户打断时停播并恢复听取。评测实际首声延迟、打断后停声延迟、误打断、漏打断、重叠语音保留率和回声触发率。[本地输入流](../../crates/lfm3-omni/src/input_stream.rs)、[Full-Duplex-Bench](https://github.com/DanielLin94144/Full-Duplex-Bench)
- **P2，真正同时听答：** 必须解决生成中持续输入、双向时间对齐、状态/缓存因果性、播放参考和交错训练样本；可能需要模型结构或训练协议变更，秩 4 LoRA 和调度器均无能力保证。Moshi 论文展示的是其专门设计的并行音频流及自身系统延迟，不是 LFM3 或本机的延迟承诺。[Moshi 论文](https://arxiv.org/abs/2410.00037)

用于对话时序的数据应保留自然停顿、重叠、打断和非打断附和。比如 [AISHELL-4](https://www.openslr.org/111/) 提供多通道会议及说话活动标注，许可页面列为 CC BY-SA 4.0；多麦克风通道并不等于干净的独立说话人轨或助手问答真值。相邻发言不能未经核验直接当作助手目标。[Full-Duplex-Bench](https://arxiv.org/abs/2503.04721) 可供独立评测设计参考，实际使用仍需逐数据源核对许可和切分。

### P1：理解语气和副语言

- **样本/目标：** 相同或近似文本、不同说话人和表达方式的音频，标注可听见的语气、强度及多标注者分布；允许不确定与弃判。先预测可观察表达，不从声音断言真实心理状态或诊断。必要时训练冻结音频表征上的小分类/回归头，再验证是否值得接入回答策略；这是建议，仓库尚无现成情绪头。[MERT 限制](../../crates/omni-music/README.md)、[RAVDESS 论文](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0196391)
- **教师：** 多人独立听标优先；自动模型只提供带来源的弱标签。对同文本不同语气及同语气不同文本做反事实配对，音频与文本分别遮蔽，检查预测确实使用声音；音高或响度本身不是情绪真值。
- **评估：** 按说话人、会话和文本家族隔离；报告宏平均 F1、各类召回、校准/弃判覆盖率，连续维度可报告 CCC；人工复核含噪声、口音与表达不一致样本。英文表演语料上的结果不能外推为自然中文可靠性。[MSP-Podcast 评测](https://lab-msp.com/MSP-Podcast_Competition/SERB/)
- **许可：** [RAVDESS](https://smartlaboratory.org/resources/speech-song-database-ravdess/) 为表演数据，列有 CC BY-NC-SA 4.0；[ESD](https://github.com/HLTSingapore/Emotional-Speech-Data) 包含中文和英文表演语音，数据使用须按发布方要求取得研究许可，代码仓库许可不自动覆盖数据。非商业和签署要求须逐项核对，未授权前不使用。

### P3：跟音乐哼唱

独立的音符、采样时钟和客观指标接口及其合成测试边界见 [哼唱评估](../humming-evaluation.md)；它不提供声学音高检测或真实哼唱证据。

- **样本/目标：** 先限定有明确主旋律的单声部任务：伴奏、主旋律音符或干净哼唱、节拍与起止时间同轴配对；许可允许时使用真实人声与乐谱，记录演唱者和曲目。多声部伴奏本身不能唯一确定应唱旋律；纯正弦信号只验证管线，不证明会哼唱。[M4Singer](https://m4singer.github.io/)、[OpenCPOP](https://github.com/wenet-e2e/opencpop)
- **教师：** 已授权的人类哼唱及其音符标注优先；经许可的合成教师可用于启动，但要记录合成器和来源。先测试 LFM3 codec 重建哼唱时的音高与清晰度上限，再尝试以已观察到的伴奏前缀预测后续声码；不能假定现有 YuE 接受 MERT 表征或直接提供同步人声。[音乐模块](../../crates/omni-music/README.md)、[codec](../../crates/lfm3-omni/src/codec.rs)
- **评估：** 曲目、演唱者和伴奏版本隔离；在独立人声音轨上报告有声召回/误报、音高准确率、八度无关的 chroma 指标、音符起始误差和实际播放相对拍点的偏差；同时报告静音、漏唱和人工听感，不能靠时间扭曲掩盖延迟。[mir_eval 旋律指标](https://github.com/mir-evaluation/mir_eval/blob/main/mir_eval/melody.py)
- **实时约束：** 对未知后续旋律只能使用已到达的信息；可明确允许固定跟随延迟，并分别测因果条件下的音乐准确性和绝对同步误差。离线已知乐谱、提前看未来及真正实时跟随须分开报告。
- **许可：** [M4Singer 数据许可](https://github.com/M4Singer/M4Singer/blob/master/dataset_license.md)为 CC BY-NC-SA 4.0；[OpenCPOP 许可](https://wenet-e2e.github.io/opencpop/liscense/)列有 CC BY-NC-ND 4.0。还须核对素材、改编、衍生数据与用途的具体权利；有歌声和乐谱不代表已提供与目标任务匹配的伴奏轨。

## 首个可执行实验提案：P0 中文音频条件短答

一个可自动核对的样例是：文字提示始终为“把听到的数字加一，用中文回答”，输入音频分别朗读“十二”和“十五”，规则程序给出“十三”和“十六”。训练时不能把数字放进文字提示；交换音频后，答案也应按规则交换。对于确认完全共享且尚不足以区分数字的声音前缀，时序任务的标签应是等待，不能用事后完整录音的答案当作当时可知的信息；两次 TTS 可能因协同发音而在前缀中泄露线索，不能假设它们天然相同。先用 Breeze 合成并用 R2T2 检查音频内容，再用未见说话人的真人录音检验迁移；R2T2 本身不是算术答案的真值。

1. **预注册数据和切分：** 提议至少 120 条训练、30 条开发、50 条最终保留，来自互不重叠的说话人/会话；同源裁剪、变速、合成变体及相同录音家族只能留在同一分组。数量不足时先报告可行性，不能宣称泛化。现有固定 10 题只作已暴露开发回归，不充当独立最终测试。[现有开发协议](../chinese-speech-rsi.md)
2. **任务：** 给短音频随机携带的数字或有限选择，要求按固定规则答复，生成的答案不能从静态提示推断；保留人工审核的答案文本和经许可的答案人声或 Breeze 朗读。训练与评估均含不同数字、噪声、说话方式及无声/交换音频负对照。
3. **实现接缝：** 增加可接收输入音频媒体的 teacher-forced 前向、答案文字损失和语音码损失；音频编码器与底座先冻结，只更新现有目标层的小 LoRA。核验媒体占位、帧错位、因果遮罩和 EOS；音频前缀不得含未来信息，缓存或预计算须绑定输入和底座哈希。验证适配器梯度非零、底座参数不变，输入交换能按对应答案改变预测，再启动短训练。[源码](../../crates/lfm3-omni/src/model.rs)、[优化器](../../crates/omni-rsi/src/speech_training.rs)
4. **对照和预算：** 比较同设备、相同解码与采样设置的冻结底座和候选；保留当前自朗读训练作为可选消融，不能当作音频条件训练。先限定与已知反证可比的 6 次更新，仅做管线和退化检查；是否增加预算须以开发结果和资源实测决定。小适配器不代表训练激活、codec、优化器和并发推理的显存/统一内存开销小。
5. **独立门槛：** 预先固定答案判定、错误类别和成对统计；候选在独立开发集的答案准确率应有可复现提升，正常结束率不得低于基线，朗读与对话分组不得明显退化，音频交换负对照必须有效。建议要求准确率提升至少 5 个百分点且成对置信区间下界大于 0；样本不足则判为证据不足，不把统计不显著解释为成功。独立最终保留集只在方案冻结后评一次，并由盲听核验可懂度与语义。
6. **发布边界：** 只有开发门槛和独立保留验证均通过，才考虑显式选择候选进行新会话试用；任何持续输出、EOS、音频依赖或前台响应退化均回退。现有 60.3%→87.2%、10/10→8/10 的候选不满足此建议门槛。[报告](../../artifacts/idle-quality-validation/quality-summary.json)

## RSI 数据、调度和晋级

每轮冻结数据快照、底座/教师/候选哈希与配置；保留人工或规则真值数据，限制合成和伪标签占比并分组报告。R2T2 的原始转写与同一系统对 codec 重建音频的转写会共享错误，只能说明一定的一致性；同一家族模型互评也不是独立真值。训练集与保留集按说话人、会话、文本、曲目及衍生家族隔离，禁止把已反复调参的开发集称为最终测试。[现有边界](../chinese-speech-rsi.md)、[语音自训练研究](https://ai.meta.com/research/publications/self-training-for-end-to-end-speech-recognition/)

递归训练可能放大伪标签偏差；模型坍缩论文展示了特定条件下的退化，而保留原始数据在另一些实验中有帮助，均不保证本项目成功。应持续保留来源多样的真实样本、人工抽检失败和长尾，并监控各轮性能、校准与样本多样性。[递归生成研究](https://arxiv.org/abs/2305.17493)、[保留原数据研究](https://arxiv.org/abs/2404.01413)

闲时训练是工程调度，不是上述论文的实证结论：建议显式开启，限定耗时、内存、温度、电源和磁盘预算；用户返回、前台推理或录音时停止发起新步，在安全点保存候选及优化器并释放设备。现有锁只协调遵循同一协议的进程，不能保证其他应用或整个 GPU 空闲；须独立测暂停延迟、前台 p95 延迟、内存峰值、耗电和恢复正确性。[现有闲时边界](../idle-rsi.md)、[语音调度与验证](../chinese-speech-rsi.md)

晋级建议写入独立不可变候选目录，校验底座、适配器、数据和报告哈希以及完整性；在同一文件系统先落临时文件、同步数据，再原子替换指向活动版本的清单并同步目录。中断后只能读取完整已验证版本，保留上一版本和可审计回滚；不在进行中的会话热换权重。当前候选加载与证据校验见[中文语音 RSI](../chinese-speech-rsi.md)；完整跨进程租约、崩溃恢复和原子晋级是否全部覆盖，仍待单独验证。

## 明确未验证

- 本机尚无证据证明音频条件回答训练有效、真实全双工成立、语气分类可靠或音乐条件哼唱可用；也没有本文各阶段的运行时间、内存、电量或延迟实测。
- LFM3 对哼唱的 codec 保真、音频条件梯度路径、长时上下文更新、声学回声环境下的效果均待实验；如前置验证失败，应停止晋级而不是增加自训练轮数。
- 用户录音仅在明确授权的范围内使用；研究和发布前分别核对模型、录音、文本、乐谱及派生数据许可。[LFM3 许可](https://huggingface.co/LiquidAI/LFM3-Omni-2B/blob/main/LICENSE)
