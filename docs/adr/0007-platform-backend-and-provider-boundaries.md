# 通用计算后端、Apple 加速层与外部能力提供方的边界

2026-11-26：承接 [ADR-0005](0005-burn-dependency-boundaries.md) 与 [ADR-0006](0006-unified-cargo-workspace-and-artifact-lifecycle.md)，明确平台解耦与可选外部 API 接入的两条架构边界。

## 决定

1. **通用计算后端与 Apple 加速层分离**：模型 crate、`omni-kernel`、`omni-api` 与桌面端通过清晰的特征与接口边界分离可移植的计算后端（通用 `wgpu` / `cpu`）和 Apple 专属加速层（`burn-ane`、`objc2-metal`、MSL passthrough、TensorOps、`mtl4`、CoreML）。通用后端下的定制算子沿用显式拒绝并回退通用 Burn/CubeCL 实现的契约，确无通用等价实现的 Apple 专属路径仅在 Apple 特征下编译或运行期显式报错。Apple Silicon macOS 的默认构建、性能路径与验收门槛不变；是否进一步开展 Windows 专项适配与打包留待解耦后另行决定。
2. **模型下载与凭据收口**：桌面端通过纯 Rust 共享下载模块完成断点续传、分片校验与线路/镜像/代理调度，不依赖本机 Python 环境；命令行脚本对齐同一套线路与环境变量约定。Token 与外部 API Key 与普通配置隔离存放（环境变量优先、独立受限权限凭据文件落盘），不进入日志、报错信息或下载清单。
3. **可选外部能力提供方（默认纯本地、显式切换）**：在提示词增强、语音转写、语音合成与文本翻译四个能力槽位引入统一的外部提供方抽象，以 OpenAI 兼容协议为标准适配器并内置 Magpie 本地网关预设。所有槽位默认仍使用本地 Burn 模型，仅在用户显式切换后才发往外部端点；外部请求失败时显式报错并提供重试或切回本地操作，不静默回退，也不在未授权时外发音频或图像。

## 后果

- `./scripts/check quick` 需保护通用特征集的依赖闭包不误引入 `burn-ane`、`objc2-metal` 或 CoreML。
- `r2t2-makepad` 全部推理引擎收口到统一的后端选择模块，不再在各引擎中分散保留独立的平台条件编译。
- 引入外部能力提供方改变了“零外部请求”的单一假设，但通过“默认纯本地 + 每槽位显式状态标识 + 禁止静默外发”守住离线与隐私边界。
