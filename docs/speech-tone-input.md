# 语气开发输入准备

`omni_rsi::speech_tone_input::prepare_development_inputs` 是独立、显式调用的 Rust 输入准备接口。它不运行模型、训练、评分或执行器，不读取保留集音频，也不发放资格。调用方随后运行的执行器及其输出均未经验证；合成标签、声学控制参数和结果不代表语气质量或人的心理状态。

接口接受现有 `ToneDataset`、`ToneEvaluationPlan`、数据根目录、`ToneInputLimits` 和取消标志。计划只能选择 `train` 或 `dev`，每个案例必须引用该分区内的记录；重复案例、重复的记录／输入条件、未知案例，以及无效或缺失的对照端点在读取音频前拒绝。遮蔽对照必须引用同一记录的完整输入和相应遮蔽输入；其他对照只检查案例结构，不证明其语义关系或评估结果。

所有记录的公开 ID、说话人、会话、派生家族和文本家族声明先统一检查，跨分区碰撞拒绝；提供了音频 SHA-256 的记录也检查声明的摘要是否跨分区相同。训练与开发的规范化文本也会比较。对 `holdout` 记录，只检查上述公开分组及可选的音频路径／摘要声明，不检查转写、来源细节、标注或参考；调用方可将这些私有字段留空，也可将保留音频路径和摘要留空。开发进程不应接收真实保留题的秘密内容。

这些都是**调用方声明的一致性检查**。它们不能证明来源、许可、分组或摘要真实，不能排除不同封装、重采样、裁剪或虚报身份造成的跨分区重复，也不验证保留音频的 PCM 独立性。返回的 `holdout_pcm_independence()` 固定为 `unverified`；即便所有开发案例均可准备，也不能据此打开正式保留集或晋级。

## 读取与遮蔽

选中的记录路径分别从 `train/` 或 `dev/` 开始，例如 `dev/example.wav`；空组件、`.`、`..`、反斜杠和绝对路径均拒绝。提供的非空 holdout 路径只能使用 `holdout/` 前缀，但不会打开。调用方提供可信的数据根目录：Unix 下先打开根目录，再逐级使用目录描述符、`O_NOFOLLOW` 和非阻塞方式打开所选普通文件，拒绝符号链接、FIFO 和目录。其他平台失败关闭。未选中的 train/dev 文件和所有 holdout 文件都不会打开。

每个选中 WAV 在一个有界字节快照中读取，并按声明 SHA-256 核验；同一快照经格式检查和 Rust 解码，得到单声道 16 kHz PCM。接受 8–384 kHz 的单声道／双声道 PCM16 或 float32 WAV，最长 20 秒；空、截断、非有限或超出 `[-1,1]` 的浮点采样被拒绝。每条记录只读取和解码一次，同一记录的多个案例共享原音快照。

- `full`：固定任务指令、该记录转写和完整 PCM。
- `audio_masked`：相同指令与转写，以及相同采样率、长度的全零 PCM。
- `text_masked`：相同指令和原 PCM，不携带转写。

调用方应只将案例提供的指令、可选转写、采样率和 PCM 作为模型输入；案例 ID 和摘要是审计元数据。调用方或执行器若通过其他渠道取得文本，接口不能阻止这种泄漏，也不能证明其实际使用了准备好的输入。

默认上限为单文件 32 MiB、累计读取 128 MiB、单条 320,000 个 16 kHz 样本、累计 19,200,000 个样本；`ToneInputLimits` 可调低但不可提高。清单最多 4096 条记录、12,288 个案例，公开元数据最多 4 MiB；路径最多 16 个子组件。原音和等长静音最多各占一份 PCM，文本遮蔽共享原音。读取、原 WAV 校验、解码和哈希循环检查取消；单次系统调用不能被取消标志抢占，文件系统响应时间不受此接口保证。

文件描述符固定了打开的目录和文件，读取后的摘要绑定实际快照，但这不是防同账号、硬链接、虚假声明或恶意文件系统的完整边界。应在受控的本地数据目录使用；保留 PCM 独立性仍须独立可信流程核验。

## 输入身份

`declaration_sha256()` 对公开分组声明按记录 ID 排序并哈希，不包含 holdout 转写、标注或参考。其域为 `omni-rsi/tone-public-declarations/v1\0`，之后是大端 u64 记录数；每条依次写入 ID、分区、说话人、会话、派生家族、文本家族、音频路径和声明的音频 SHA-256，均以大端 u64 字节长度前缀。

`pcm_sha256()` 使用 `omni-rsi/tone-pcm/v1\0` 域、16 kHz 的大端 u32、样本数的大端 u64 和各样本的 f32 位模式小端编码；正负零按正零编码。`input_sha256()` 使用 `omni-rsi/tone-prepared-input/v1\0` 域，依次对运行 ID、分区、声明摘要、案例 ID、记录 ID、输入条件、固定指令、实际转写或空串、源 WAV 摘要和 PCM 摘要加入大端 u64 长度前缀，再加入大端 u32 采样率。摘要绑定准备结果，不认证来源或证明模型执行。

旧的 `ToneDataset::validate` 和 `ToneEvaluationPlan::evaluate` 行为不变：它们验证整个数据集的音频，包含声明为 holdout 的记录，不适合作为盲保留开发读取入口。真实中文语气效果仍需许可、独立真人标注、保留分歧、未见来源、噪声条件和人工听审；本切片没有提供这些证据。
