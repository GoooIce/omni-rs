# TTS long-form: segmentation and aligned limits

Scope (approved 2026-11-24): lift the hard caps that stop long speech text by splitting a speech script into speech texts, align the per-synthesis limits with upstream `breezeblue-ai/breeze-tts` (at most 1500 frames, prompt plus generated frames within 2048 positions), wire it into the Makepad UI, the CLI and the HTTP API, and commit everything. A validation ticket for single-generation long audio is GitHub issue #91.

State: branch `tts-long-form` holds the baseline (five commits on top of `1373a67`) and the TTS work (three commits: crate and CLI, HTTP API and Makepad engine, documentation). `main` is untouched and nothing is pushed. The TTS work: `crates/breeze-tts` (splitter, script state machine, `frame_ceiling`, CLI `--text-file`), `crates/omni-api` (step-driven script engine), `prototypes/makepad/src/tts_engine.rs`, `docs/breeze-tts.md`, `GLOSSARY.md` and `VALIDATION.md`. The second round of design questions is still waiting for answers: the playback policy for a long script in Makepad, where the voice anchor comes from, and the term for the shared reference. Until the playback policy is chosen, a Makepad script longer than the 60-second ring rebuffers periodically.

Validation is recorded in `VALIDATION.md`, dated 2026-11-24, with the raw files under `artifacts/tts-long-form/`. In short: the crate's 44 CPU unit tests pass and the crate also passes under Metal; `omni-api` is clean under strict Clippy with 28 tests passing and its release server spoke a 276-character script as 3 speech texts end to end; the Makepad unit tests pass under Metal; the native TTS harness passed its 23 checks twice on the muted real device; a 2699-character prose script of 18 speech texts and 668.88 seconds of audio was generated in 946.24 seconds at RTF 1.42 with no ceiling hit; the real Makepad app spoke a 275-character script as 3 speech texts and saved a matching WAV.

Two things are red for reasons outside the TTS work. `./scripts/check metal` stops at `test-omni-rsi`: `crates/omni-rsi/tests/backend_source_tree.rs` pins an implementation hash (`425b2d…`) that matches neither the current inputs (`2d60e1…`) nor `main` (`5d8a2c…`); only the three hashed lockfiles changed since `main`. The pin was not touched, because it guards RSI training checkpoints. The native harness reports `complete: false` because its last step asks the ASR for an exact transcript and the unchanged ASR CLI was transcribing that same official recording unstably during the session.

Open findings, none introduced by the seams: pauses of one to three seconds occur in about half of the sampled voices regardless of segmentation; one speech text of the 18 drifted to a brighter voice for about six seconds and the local ASR then answered in English; the Makepad reader speaks with a fixed seed, so the voice that seed samples for the opening sets the pace of the whole script. Nothing has been listened to by a person.

Current checkpoint: `artifacts/task-checkpoint.json` (objective, accepted decisions, changed paths, next command). The previous summary, for the native-only task, is kept at `artifacts/native-only-20261112-notes.md`.
