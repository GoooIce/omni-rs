# TTS long-form: segmentation, aligned limits and two-step playback

Scope (approved 2026-11-24, settled 2026-11-25): lift the hard caps that stop long speech text by splitting a speech script into speech texts, align the per-synthesis limits with upstream `breezeblue-ai/breeze-tts` (at most 1500 frames, prompt plus generated frames within 2048 positions), wire it into the Makepad UI, the CLI and the HTTP API, and commit everything. A validation ticket for single-generation long audio is GitHub issue #91.

State: branch `tts-long-form` holds the work as commits on top of `main` (`1373a67`): five for the baseline that was already in the working tree; `b43ea25` splitter, script state machine, `frame_ceiling` and the CLI; `5d42cc1` the HTTP API and the Makepad engine; `c1151c1` documentation; then `b4d3cc0` refreshed RSI identity pin, `57442d9` the term Voice anchor, `6d740a6` the API clamp, `92b8cd8` two-step playback, and the evidence commit that carries this note. `main` is untouched and nothing is pushed.

Behavior: a script is split at sentence punctuation into speech texts of at most 128 text tokens (24 for the first). Each speech text is one speech synthesis with the upstream ceiling. When the speaker gives no reference recording, the opening audio is recorded as the voice anchor once it reaches three seconds and every later speech text clones it. In Makepad a script of several speech texts plays in two steps: the opening as it arrives, then the rest on its own output stream once the adaptive policy has banked its lead; the ring is sized to the script's estimated duration, capped at 256 MiB. The HTTP API clamps `max_frames` into `1..=1500` as upstream does.

Validation is in `VALIDATION.md`, section 2026-11-24, with raw files under `artifacts/tts-long-form/`. `./scripts/check metal` passes on `92b8cd8` (52 steps). `./scripts/check quick` passes at every commit through the hook. The native TTS harness passes all 24 TTS checks on the muted real device, including a 71.04-second script of three speech texts with no underrun on either stream. Its report stays `complete: false` because its last step wants an exact ASR transcript and the app drops the final period; the app built from `8b12275`, before this work, drops it too.

Open findings, none introduced by the seams: pauses of one to three seconds occur in about half of the sampled voices regardless of segmentation; one speech text of the 18 in the eleven-minute run drifted to a brighter voice for about six seconds and the local ASR then answered in English; the Makepad reader speaks with a fixed seed, so the voice that seed samples for the opening sets the pace of the whole script; the wait estimate shown while the rest is banked runs long. Nothing has been listened to by a person, and playback on a real device has only been exercised up to 71.04 seconds.
